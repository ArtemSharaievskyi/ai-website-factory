# Requirement traceability

Every planning decision contains a stable decision ID, category, one or more approved-brief references, fixed-stack references where applicable, rationale, confidence, unresolved dependency, and whether user confirmation is required. Examples include route creation from approved page scope, Storage from approved uploads, and omitted administration from the absence of an approved management requirement.

Planning acceptance rejects plans with missing traceability. This prevents recommendations or provider inference from silently becoming approved product scope.
