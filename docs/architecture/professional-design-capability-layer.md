# Professional Design Capability Layer

Status: CURRENT_IMPLEMENTATION / Phase 8 Emil motion and independent design review

The Design Agent creates exactly three materially distinct directions. The host then enriches the provider result through the bounded professional capability pipeline. The provider transport does not receive the host-only professional package; the package is bound after generation and persisted inside the current design-direction document.

## Capability boundary

- The previously evaluated paid design-generator candidate is excluded by policy: `required=false`, `active=false`, and `credentialRequired=false`. No runtime tool, API, MCP, or credential path exists for it; the prior blocked report remains historical evidence only.
- Fontpair is a dedicated bounded read-only adapter with an exact `https://fontpair.co` origin allowlist. It enforces HTTPS, response, timeout, retry, redirect, content-type, cache, and deduplication bounds; normalized pairs are checksum-bound to every `TypographyDecision`.
- 21st.dev, React Bits, free Magic UI registry metadata, and the existing shadcn/ui base participate in every direction as read-only research sources. They cannot write source or install dependencies; source candidates are compared, deduplicated, and dispositioned before implementation authority is applied.
- Impeccable is represented by approved immutable skill evidence plus a host-controlled deterministic anti-pattern detector. The detector is read-only.
- Emil Kowalski design and animation guidance is pinned to the audited `emilkowalski/skills` revision `d23d7f88a2e21c9e4b1418c7abe420f5c1052ba7` under its MIT license. The five requested skills are imported from an explicit upstream checkout through staging, static review, human curation evidence, approval, and immutable promotion; revision-qualified registry IDs and normalized content checksums preserve currentness while older snapshots remain history. `emil-design-eng` is assigned primarily to FrontendImplementationAgent, `animate` is motion-task-only, and the three animation advisory/review skills have no source or canonical write authority.
- Independent `DesignReviewAgent` is required for substantial public/approved-design surfaces and remains separate from Visual Regression, UX Critic, Accessibility, and FrontendImplementation. It consumes approved Design, Design System, AntiAISlop, Impeccable, screenshot, and responsive evidence and reports hierarchy, typography, spacing, layout, surfaces, color, iconography, component consistency, motion, interaction polish, responsive craft, distinctiveness, and AI-slop findings.
- `AnimationReviewAgent` is required only when meaningful motion is activated. It is read-only and checks justification, frequency, duration, easing, origin, scale, interruption, GPU/layout properties, enter/exit behavior, reduced motion, hover gating, and token cohesion. `MotionImprovementAdvisor` and `AnimationOpportunityFinder` produce checksum-bound plans/suggestions only; zero-motion is a valid opportunity result.
- Review snapshots bind implementation checksum, approved Design checksum, Design System version, and motion-token checksum. The lightweight orchestrator rejects missing bindings for Design/Animation review and fails closed when any binding changes. Release Readiness blocks on blocking Design or Animation findings. No provider calls, generated-project mutation, canonical mutation, or production dependency is introduced.
- Motion for React is optional. The exact approved package is `motion@12.43.0`; it is selected only by a `MotionDecision` with `MOTION` suitability and requires a user-approved `design-dependency-amendment` before implementation starts.
- Google Fonts metadata, Color Hunt palette inspiration, and the official Aceternity UI registry are exposed through the existing read-only design-source boundary. They remain advisory external evidence; they do not create agents, Design authority, install authority, or persistence authority.
- Typography selections require Design approval, an explicit rationale, only approved weights/subsets, and a `next/font/google` self-hosting plan. Runtime Google stylesheet/provider requests are blocked by the implementation quality checklist and represented in German compliance evidence.
- Color Hunt candidates are converted into semantic project tokens and checked for contrast; unchanged palette copying is blocked unless the approved brand explicitly matches it. Aceternity candidates are namespaced, provenance-bound, adaptation-required, reduced-motion aware, and installable only for a component after task authority, dependency review, and license/entitlement checks.

## Contract flow

`DesignDirection` → `DirectionDesignCapability` → `DesignCapabilityPackage` → explicit user `SelectedDesign` binding → implementation/start gate.

Each direction binds a visual system, typography decision, motion decision, interaction contracts, tool provenance, pass evidence, contract checksum, and currentness. The three-direction validator requires exactly three directions and distinct visual token checksums. The Implementation Agent and Orchestrator verify every selected checksum before execution.

The current reconciliation closes the bounded Phase 8 scope and its frontend resource extension: live Fontpair normalization, seven capability-covered official design skill records, the existing four read-only component sources per direction, optional Google Fonts/Color Hunt/Aceternity discovery, exactly three distinct directions, explicit user selection, current Emil motion/design provenance, independent design and animation review, and optional Motion for React dependency approval. Final hardening, customer-project E2E, and deployment remain outside this phase.
